# Техническое задание

**Голосовой ИИ-ассистент (умная колонка) Noctis**

Документ описывает требования к системе в том объёме, в котором они реализованы и проверены. Планируемые, но не выполненные работы в него не входят.

## 1. Общие сведения

| | |
|---|---|
| Наименование | Noctis — голосовой ИИ-ассистент в виде умной колонки |
| Имя ассистента, слово пробуждения | «Нильс» (Nils); дополнительно — «Alexa» |
| Назначение | Голосовое управление временем, таймерами, будильниками, музыкой, получение ответов на вопросы и прогноза погоды; настройка колонки с телефона и из браузера |
| Состав | сервер, прошивка колонки, мобильное приложение, сайт с веб-кабинетом, инструменты обучения слова пробуждения, документация |
| Условия работы | локально, на компьютере владельца под Windows, без WSL; обязательной зависимости от облачных ИИ-сервисов нет |

## 2. Цели и ограничения

**Цели.** Создать работающую умную колонку с распознаванием речи, языковой моделью и синтезом речи на собственном компьютере, с управлением через приложение и сайт, на пяти языках (русский, английский, испанский, немецкий, французский; русский — основной).

**Обязательные ограничения.**

1. Языковая модель — только Vikhr-Nemo-12B (через Ollama); другие модели не используются.
2. Всё работает нативно в Windows, WSL не применяется.
3. Источники музыки — только личная библиотека пользователя, каталог Jamendo и интернет-радио.
4. Push-уведомления и Firebase Cloud Messaging не используются.
5. Хранилище данных — SQLite, схема меняется миграциями Alembic.
6. Документация и текст проекта — на русском; приложение и сайт — на пяти языках.
7. Аппаратная часть: плата ESP32-S3 (N16R8), микрофон INMP441, усилитель MAX98357A, экран SSD1306; часов реального времени (DS3231) и аудиокодека (ES8388) в составе нет.

## 3. Состав системы

| Компонент | Папка | Технологии |
|---|---|---|
| Сервер | `server/` | Python 3.12, FastAPI, SQLAlchemy, Alembic, SQLite, faster-whisper, Ollama, Silero TTS |
| Прошивка | `firmware/` | ESP-IDF 5.x (сборка PlatformIO), Си/Си++, esp-sr, microWakeWord (TFLite Micro) |
| Мобильное приложение | `app/` | Flutter 3.47, Android |
| Сайт и веб-кабинет | `site/` | статические страницы, JavaScript; раздаются сервером |
| Обучение слова пробуждения | `wakeword/` | Python, TensorFlow, microWakeWord, Silero |
| Документация | `docs/` | Markdown, схемы SVG |

## 4. Функциональные требования

### 4.1. Голосовой конвейер

- **Ф-1.** Колонка непрерывно слушает микрофон; слово пробуждения распознаётся на самой плате, до его произнесения аудио на сервер не передаётся.
- **Ф-2.** После слова записывается команда; пауза в речи около 0,7 с завершает запись. Если за 6 с речи нет, колонка возвращается в ожидание.
- **Ф-3.** Сервер распознаёт речь (faster-whisper large-v3), формирует ответ языковой моделью Vikhr-Nemo-12B и озвучивает его (Silero; русский женский голос Xenia, мужской Aidar; голоса для остальных языков тоже предусмотрены).
- **Ф-4.** Озвучивание начинается по мере генерации ответа (по предложениям); подача звука на колонку выравнивается по времени, чтобы воспроизведение не прерывалось.
- **Ф-5.** Во время ответа слово пробуждения не слушается, чтобы колонка не «будила» сама себя.
- **Ф-6.** Поддержаны пять языков распознавания и ответа; язык выбирается в настройках колонки.
- **Ф-7.** Поддержаны характеры ассистента (дружелюбный, официальный, шутливый, саркастичный, мотивирующий, спокойный, энергичный, мудрый, заботливый, нейтральный) с предпрослушиванием примера реплики.

### 4.2. Слово пробуждения

- **Ф-8.** Пользователю доступны два слова: «Нильс» (по умолчанию) и «Alexa». Другие значения сервер отклоняет.
- **Ф-9.** «Нильс» распознаёт микромодель microWakeWord (≈ 60 КБ), «Alexa» — модель WakeNet из esp-sr. Выбор движка и перезапуск при смене слова выполняются автоматически, перепрошивка не нужна.
- **Ф-10.** Модель «Нильс» хранится на сервере; колонка скачивает её по хэшу, проверяет SHA-256 и структуру до записи в отдельный раздел флеш-памяти, затем перезагружается. Без модели колонка работает на запасном слове и показывает `NO WAKE MODEL`.
- **Ф-11.** Предоставлены инструменты обучения собственной модели слова на Windows без GPU (подготовка данных, синтез примеров, аугментация, обучение, проверка, упаковка в контейнер NWWM, загрузка на сервер).

### 4.3. Время, таймеры, будильники

- **Ф-12.** Колонка получает время по SNTP, а при его недоступности — от сервера; часовой пояс настраивается. Часы реального времени не используются.
- **Ф-13.** Голосовые команды: узнать время, поставить таймер («поставь таймер на пять минут»), будильник («разбуди меня в 7:30 по будням»), отменить.
- **Ф-14.** Будильники — однократные и по дням недели; звонок одной из мелодий (`default`, `soft`, `rooster`, `beeps`) до 60 с; расписание хранится на колонке в энергонезависимой памяти и сверяется с сервером.
- **Ф-15.** Звонок останавливается кнопкой, словом пробуждения или командой «стоп».
- **Ф-16.** Таймеры и будильники создаются и редактируются также из приложения и веб-кабинета; таймер можно поставить на паузу и продолжить.

### 4.4. Музыка

- **Ф-17.** Источники: личная библиотека пользователя (MP3, FLAC, Ogg, WAV; загрузка через приложение, сайт или API), каталог Jamendo и интернет-радио. Других источников нет.
- **Ф-18.** Jamendo: поиск по названию, исполнителю и жанру (в том числе по русским названиям жанров), повторные запросы при пустых ответах, кэш на 30 минут, отображение лицензии Creative Commons.
- **Ф-19.** Голосовое управление: включить жанр, исполнителя или станцию, пауза, продолжить, следующий трек, громкость.
- **Ф-20.** Музыка декодируется на сервере (Python-библиотека `miniaudio`, ffmpeg не нужен) и передаётся на колонку потоком PCM; на колонке — буфер воспроизведения в PSRAM. Во время голосовой команды музыка ставится на паузу.
- **Ф-21.** Поддерживаются плейлисты пользователя.

### 4.5. Погода

- **Ф-22.** Колонка отвечает голосом, какая сегодня погода в любом назваемом месте («какая погода в Казани»); источник — Open-Meteo, ключ не нужен.
- **Ф-23.** Русские названия городов приводятся к начальной форме и склоняются при озвучивании (pymorphy3).
- **Ф-24.** В настройках колонки есть поле «Домашний город»: оно используется, когда город в команде не назван.

### 4.5а. Диалог

- **Ф-25.** История диалогов (реплика пользователя, ответ, время этапов) сохраняется, если включена в настройках, и доступна в приложении и кабинете.

### 4.6. Учётные записи и роли

- **Ф-26.** Регистрация с согласием на обработку данных, вход, обновление токена, выход, восстановление и смена пароля.
- **Ф-27.** Роли «пользователь» и «администратор». Администратор создаётся утилитой `server/tools/create_admin.py`.
- **Ф-28.** Страница администратора (открывается по Alt+X): список пользователей и колонок, блокировка, сброс пароля, удаление, журнал действий. Пароли пользователей администратору недоступны.
- **Ф-29.** Привязка нескольких колонок к одной учётной записи; удаление колонки из приложения и сайта (колонка при этом сбрасывается к заводским настройкам).

### 4.7. Настройка колонки

- **Ф-30.** Сопряжение: колонка включает Bluetooth и показывает на экране имя и 8-значный код; приложение создаёт колонку на сервере и передаёт ей по BLE адрес сервера, токен устройства и данные Wi‑Fi. Адрес сервера в код не зашит.
- **Ф-31.** Смена сети Wi‑Fi у колонки, находящейся на связи, без сброса: при неудаче колонка возвращается в прежнюю сеть.
- **Ф-32.** Повторная настройка по Bluetooth без потери личности колонки: удержание кнопки 3 с либо автоматически после 10 минут без связи с сервером.
- **Ф-33.** Внешняя кнопка на GPIO11 (и кнопка BOOT) работают одинаково: 3 с — режим настройки; 5 с при включении питания — сброс к заводским настройкам.
- **Ф-34.** Настройки колонки (слово, голос, характер, язык, громкость, часовой пояс, домашний город) хранятся на сервере и в памяти колонки, применяются без перезагрузки.
- **Ф-35.** Обновление прошивки по воздуху: проверка SHA-256 до переключения слота, обновление только вперёд, откат при неподтверждённом запуске за 90 с.
- **Ф-36.** Экран SSD1306 показывает время, слово пробуждения, ближайшие таймер и будильник или название трека, а также сообщения о состоянии (сопряжение, ошибки, обновление).
- **Ф-37.** При потере связи колонка переподключается к серверу в течение 10 с, а при обнаружении слова без связи подаёт слышимый сигнал.

### 4.8. Мобильное приложение (Android)

- **Ф-38.** Вход и регистрация, добавление колонки по Bluetooth, настройки, таймеры и будильники, музыка, история, профиль; пять языков, светлая и тёмная темы; оформление совпадает с сайтом.
- **Ф-39.** Адрес сервера вшивается при сборке; скрытое окно (семь касаний по логотипу) позволяет проверить соединение и сменить адрес без пересборки.
- **Ф-40.** Раздел «Мои данные»: копирование выгрузки данных, очистка истории.
- **Ф-41.** Сборка подписанных APK и AAB скриптом `app/tools/build_android.ps1`.

### 4.9. Сайт и веб-кабинет

- **Ф-42.** Лендинг и кабинет на пяти языках, светлая и тёмная темы, единая палитра с приложением (`tokens.json`).
- **Ф-43.** Сайт раздаётся самим сервером с того же адреса, что и API (CORS не нужен); отдаётся только список разрешённых типов файлов.
- **Ф-44.** Кнопка скачивания APK; для iPhone указано, что приложение в разработке.
- **Ф-45.** Вкладка «Мои данные»: выгрузка всех данных в файл JSON, очистка истории диалогов, удаление учётной записи с подтверждением паролем. Действия выполняются только по нажатию пользователя.
- **Ф-46.** Поле «Адрес сервера» для проверки (семь нажатий по логотипу).

## 5. Требования к безопасности и приватности

- **Б-1.** Устройства без токена отключены по умолчанию; токен устройства хранится на сервере в виде хэша и передаётся в заголовке, не в адресе.
- **Б-2.** Ключ подписи токенов создаётся случайно при первом запуске и хранится в `server/data/secret.key`; ключ из примера конфигурации не применяется.
- **Б-3.** Пароли хранятся в виде хэшей (scrypt); политика отклоняет распространённые, последовательные и содержащие почту или имя пароли; токен сброса одноразовый, действует 30 минут, действителен только последний; смена пароля завершает все сеансы.
- **Б-4.** Сервер ограничивает частоту запросов.
- **Б-5.** Заголовки безопасности на всех ответах; для страниц сайта — строгая политика CSP (`script-src 'self'`), встроенных скриптов нет.
- **Б-6.** Секреты (ключи, токены, пароли, JWT) скрываются в журналах; утилита `server/tools/scan_secrets.py` ищет их в git, архивах и журналах.
- **Б-7.** Пользователь может выгрузить свои данные, очистить историю и полностью удалить учётную запись; удаление стирает его колонки, историю, таймеры, будильники, загруженную музыку, а онлайн-колонку сбрасывает.
- **Б-8.** Запись звука на сервере по умолчанию не сохраняется.
- **Б-9.** Проверка зависимостей (`pip-audit`) и сведения о лицензиях зафиксированы в документации.

## 6. Требования к данным

- Хранилище — SQLite; схема управляется миграциями Alembic (применяются при запуске).
- Основные сущности: пользователи и роли, сеансы, сброс пароля, колонки и их настройки, связи «пользователь — колонка», таймеры, будильники, треки, плейлисты, история диалогов, версии прошивки, модели слов, журнал администратора. Схема — `docs/database-schema.svg`.
- Резервная копия: `python -m noctis_server.backup`.

## 7. Требования к аппаратной части

Схема подключения — `docs/hardware-wiring.svg`.

| Модуль | Подключение |
|---|---|
| ESP32-S3 DevKitC-1 N16R8 (16 МБ flash, 8 МБ PSRAM) | питание и прошивка по USB (порт UART) |
| Микрофон INMP441 | SD → GPIO16, SCK → GPIO17, WS → GPIO18, L/R → GND, VDD → 3V3 |
| Усилитель MAX98357A | BCLK → GPIO5, LRC → GPIO6, DIN → GPIO7, VIN → 3V3 |
| Экран SSD1306 (I²C, 0x3C) | SDA → GPIO8, SCL → GPIO9 |
| Внешняя кнопка | GPIO11 → GND (внутренняя подтяжка) |

Разметка флеш-памяти: два слота приложения (OTA) по 3 МБ, раздел моделей esp-sr 8 МБ, раздел модели слова 1 МБ, раздел звуков.

## 8. Требования к программной среде

- Сервер: Windows 10/11, Python 3.12, видеокарта NVIDIA для голосовой части (для RTX 50xx — PyTorch с CUDA 12.8 и новее), Ollama.
- Прошивка: PlatformIO (ESP-IDF 5.x), плата ESP32-S3 N16R8.
- Приложение: Flutter 3.47, Android SDK.
- Обучение слова пробуждения: Python 3.12, около 40 ГБ свободного места, GPU не требуется.
