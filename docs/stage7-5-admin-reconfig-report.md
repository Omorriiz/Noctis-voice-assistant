# Дополнение к этапам 6–7: администратор, адрес сервера, смена Wi‑Fi без сброса

Этапы 8 и 9 не затрагивались. Работы выполнены по вашему подтверждению: админ-аккаунт и страница; поле адреса сервера (7 нажатий) с проверкой соединения;
смена Wi‑Fi и адреса сервера без сброса платы; на сайте страница администратора по Alt+X.

## 1. Администратор
- **Аккаунт** создаётся командой (пароль вводите вы, пароля по умолчанию нет, в файлах и аргументах он не хранится):
  ```powershell
  cd server
  .venv\Scripts\python.exe tools\create_admin.py --email you@example.com --name "Админ"
  ```
  Команда применяет миграции, создаёт пользователя с ролью `admin` или назначает ею существующего; `--demote` снимает права.
- **Страница** `admin.html`: открывается сочетанием **Alt+X** на любой странице сайта (в меню её нет, `noindex`), дальше — вход почтой и паролем администратора.
  Обычная учётная запись после входа получает отказ и токены не сохраняются. Токены администратора живут только в `sessionStorage` вкладки.
- **Что видно:** сводка (пользователи, колонки, онлайн, таймеры, будильники, треки, реплики); список пользователей с поиском (имя, почта, роль, статус,
  колонки онлайн/всего, дата регистрации, последний вход); карточка пользователя (язык, история, треки, согласие на обработку данных, его колонки: статус, прошивка,
  когда были в сети, язык, слово, число таймеров и будильников); журнал действий.
- **Что можно:** отключить/включить учётную запись, сбросить пароль, удалить учётную запись, удалить колонку. Учётные записи администраторов (и свою) через страницу изменить нельзя.
- **Пароли не показываются**: на сервере хранятся только необратимые хэши (scrypt), прочитать пароль невозможно. Вместо этого «Сбросить пароль» выдаёт одноразовый временный пароль
  (показывается один раз) и завершает все сессии пользователя.
- **Приватность:** содержимое диалогов администратору не отдаётся — только счётчики.
- **Журнал** (`audit_log`, миграция `0004`): вход администратора и каждое изменяющее действие (кто, что, над кем, IP). Добавлено поле `users.last_login_at`.
- API: `/api/v1/admin/*` (только роль admin; 401/403 для остальных).

## 2. Адрес сервера для проверки
- **Приложение и сайт:** 7 быстрых нажатий на логотип (на экране входа и в «Профиле»; на сайте — на странице кабинета) открывают поле «Адрес сервера» с кнопками
  **«Проверить соединение»** (запрос `/health`, 5 секунд), «Адрес по умолчанию» и «Сохранить». Адрес должен начинаться с `http://` или `https://`. Он сохраняется на устройстве/в браузере.
  У обычных пользователей поле скрыто. В приложении раньше оно было только в «Профиле» (после входа) — теперь доступно и на экране входа, иначе сменить адрес до входа было невозможно.

## 3. Смена Wi‑Fi и адреса сервера без сброса платы
Два случая:

**а) Колонка на связи (приложение и сайт).** «Сменить сеть» → сервер шлёт плате команду `set_wifi`; плата переходит в новую сеть. Если за 45 с не удалось подключиться **и** связаться с сервером,
плата возвращается в прежнюю сеть и сообщает об этом (`wifi_result`). Пользователь видит: «Готово», «Не удалось подключиться, колонка осталась в прежней сети» или «Колонка не ответила».
Пароль только пересылается: не сохраняется, не пишется в журнал (проверено тестом и вручную в браузере).

**б) Колонка не в сети (только приложение, по Bluetooth).** Серверу плата недоступна, поэтому нужен Bluetooth. Память платы не позволяет держать BLE одновременно с микрофоном и распознаванием
(это ограничение уже было при первом сопряжении), поэтому плата **перезагружается в режим настройки** — с сохранением своей личности (`device_id` и токен). Войти в него можно:
- удержанием **BOOT 3 секунды** во время работы (не во время звонка);
- автоматически, если сервер недоступен **10 минут** (через 2 минуты на экране подсказка «hold BOOT 3s»).
Окно настройки открыто 10 минут, потом плата возвращается к работе. В приложении: «Колонка» → «Настроить по Bluetooth» → код с экрана → Wi‑Fi. Приложение отправляет **новый адрес сервера** и Wi‑Fi;
устройство на сервере не создаётся и не удаляется, секрет платы приложению не нужен. Это решает и смену IP ноутбука (например, в мобильной точке доступа).

Протокол: `command {name:"set_wifi", ssid, password, request_id}` (сервер → плата); `wifi_result {request_id, state: ok|failed, error}` (плата → сервер); endpoint `noctis-config` принимает `{"server","tls"}` без `device_id`/`token`.
REST: `POST /api/v1/devices/{id}/wifi` (202; 409 если колонка не на связи или смена уже идёт), `GET /api/v1/devices/{id}/wifi` (none/pending/ok/failed/timeout).

## 5. Не проверено / ограничения
- **Прошивка не прошита в настоящую плату**: собирается и проверена на хосте и в виртуальной колонке, но смену сети, 3‑секундное нажатие BOOT, окно Bluetooth-настройки на реальной плате и телефоне я проверить не мог.
  Если что-то не сработает, начните с `firmware/main/netwatch.c` и `provisioning.c`. Чтобы получить новую прошивку, её надо загрузить (`pio run -t upload`) — до этого плата работает по-старому.
- BOOT удерживается 3 с **во время работы**; удержание 5 с **при включении** по-прежнему стирает настройки (старый механизм).
- Пока плата не обновлена, кнопка «Сменить сеть» ничего не сделает: старая прошивка команду `set_wifi` не знает (в итоге — «Колонка не ответила»).
- Пароль Wi‑Fi идёт через сервер по `http` в вашей сети; для публичной работы нужен HTTPS (этап 8).
- Приложение `1.1.0` собрано как APK; адрес сервера по умолчанию — `http://192.168.0.136:8000`, для мобильной точки доступа задаётся 7 нажатиями на логотип.
