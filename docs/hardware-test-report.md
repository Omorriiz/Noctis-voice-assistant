# Проверка на реальной плате (ESP32-S3 N16R8): найденные ошибки и исправления

Дата: 17.10.2026. Плата: ESP32-S3 N16R8, INMP441 + MAX98357A + SSD1306, ESP-IDF 5.5.3 (PlatformIO). Сервер: Windows, RTX 5060 Laptop (8 ГБ),
Whisper large-v3, Silero (Ксения), Vikhr-12B (Ollama). Проверка велась по журналу UART (COM5) и по журналу сервера.

## Что проверено и работает

| Область | Результат |
|---|---|
| Загрузка, модель «Нильс» (microWakeWord) из раздела `wakeword`, голосовые модели esp-sr | работает |
| BLE-сопряжение с ПК (`server/tools/pair_device.py`), передача Wi-Fi и ссылки на сервер | работает |
| Подключение к серверу по WebSocket, `device_info`, `time_sync`, SNTP | работает |
| Синхронизация расписания сервер → плата (NVS), срабатывание таймера и будильника на самой плате | работает |
| Голосовое уведомление сервера о сработавшем таймере/будильнике | работает |
| Слово пробуждения → запись → Whisper → команда («который час» — навык, остальное — Vikhr) → озвучивание | работает |
| Музыка: поток PCM 16 кГц с сервера, пауза/продолжить, конец потока (30 с, потеряно 0 Б, опустошений буфера 0) | работает |
| Экран SSD1306 | работает (при неплотном контакте возможен пропуск — см. ниже) |

## Найденные ошибки (все исправлены, кроме отмеченных)

| № | Симптом | Причина | Исправление |
|---|---|---|---|
| 1 | `BLE_INIT: hci inits failed`, сопряжение не стартует | Bluetooth не хватало внутренней памяти после загрузки WakeNet и Wi-Fi | Несопряжённая плата запускает только BLE-сопряжение (без микрофона и распознавания), затем перезагружается |
| 2 | `noctis-config: error` при сопряжении | Адрес сервера с `http://` и `/` (плата принимает только `host:port`) | `pair_device.py` сам очищает адрес |
| 3 | `assert failed: block_locate_free` после сохранения расписания | Загрузка расписания из NVS клала ~2,5 КБ на стек main_task (3,5 КБ) → порча кучи | Буферы расписания — статические; стек main_task 8 КБ |
| 4 | Крах `LoadProhibited` в `esp_event_loop_run_task` после «Wi-Fi подключён» | Обработчик got_ip запускал WebSocket в задаче событий со стеком 2,3 КБ | Стек системной задачи событий 6 КБ |
| 5 | `stack overflow in task Tmr Svc` при переподключении | Блокирующие `stop/start` WebSocket в колбэке таймера FreeRTOS (стек 2 КБ) | Отдельная задача `ws_retry`; стек таймеров 4 КБ |
| 6 | «Ключевое слово услышано» ≈ 33 раза в секунду | Флаг «слово услышано» у microWakeWord залипал, если сервер недоступен | Сброс детектора при неиспользованном срабатывании |
| 7 | Пауза переподключения к серверу доходила до 40 с | Обрыв приходит двумя событиями, и пауза удваивалась дважды; после возврата Wi-Fi не было немедленной попытки | Идемпотентное планирование + немедленное подключение при получении IP |
| 8 | Wi-Fi подключается 20–44 с (причина 201, «точка не найдена») | Быстрый поиск и 40 МГц при слабом сигнале | Поиск по всем каналам, ширина 20 МГц, без энергосбережения; подключение ≈ 3,5 с |
| 9 | Свободно 22 КБ внутренней памяти, минимум 1 КБ | AFE 50 КБ, стеки 31 КБ, Wi-Fi 47 КБ | AFE во внешней PSRAM, выделения > 4 КБ в PSRAM, меньше буферов Wi-Fi, без IRAM-оптимизации Wi-Fi: свободно ≈ 42 КБ, минимум 29 КБ |
| 10 | Экран иногда «не найден» | Неплотный контакт на макетной плате | Шесть попыток обнаружения при запуске |
| 11 | Распознавание речи 7,6 с, ответ ≈ 16 с | Видеопамять 8 ГБ заполнена (Vikhr 23 % на CPU + Whisper float16) | Whisper по умолчанию `int8_float16` (`NOCTIS_WHISPER_COMPUTE`) |
| 12 | Загрузка прошивки: ошибка кодировки скрипта `flash_models.py` | Русский текст в cp1251 при перенаправленном выводе | Запускать с `PYTHONUTF8=1`; добавлен `NOCTIS_SKIP_MODELS=1` (не перепрошивать модели) |

Журнал платы теперь пишет: память по этапам запуска (`[heap]`), раз в минуту — свободную память и запас стека задач, причину отключения Wi-Fi, канал и уровень сигнала.

## Не исправлено / ограничения

1. **Wi-Fi периодически пропадает на 6–15 с (каждые 2–4 минуты), причина 200 «beacon timeout» и 201 «точка не найдена», при сигнале −55…−65 дБм и неактивной плате.**
   Это проявление на стороне точки доступа/радиоэфира; прошивка восстанавливает связь и сервер за секунды. Рекомендация: канал 1, 6 или 11, ширина 20 МГц,
   отключить автоматический выбор канала на роутере; ближе к роутеру; питание платы от качественного блока (помехи по питанию).
2. Сброс настроек удержанием BOOT при включении на ESP32-S3 не работает (BOOT при старте переводит чип в режим загрузчика). Надёжный способ — `pio run -t erase`.
3. Не проверены: OTA, звук (качество тона/музыки на слух), остановка звонка кнопкой BOOT, длительная работа (часы), Jamendo (нужен ваш `client_id`), радио.
4. Задержка ответа голосового конвейера (≈ 10–16 с на первом запросе) определяется видеопамятью ноутбучной GPU; для заметного ускорения нужна GPU с большей памятью или меньшая модель.
5. Опечатка в Wi-Fi при сопряжении исправляется только полным сбросом/перепрошивкой; автоматический возврат в режим сопряжения при долгом отсутствии сети не реализован.

## Как повторить

```
server\.venv\Scripts\python.exe -m noctis_server
firmware:  set PYTHONUTF8=1 ; ..\..\tools_venv\Scripts\pio.exe run -t upload     (NOCTIS_SKIP_MODELS=1 — без перепрошивки моделей)
server\.venv\Scripts\python.exe tools\pair_device.py --name NOCTIS_XXXXXX --pop <код> --server 192.168.0.136:8000 --device-id <id> --token <token> --ssid "<сеть>" --password "<пароль>"
```
Страница проверки: `http://localhost:8000/console`.
