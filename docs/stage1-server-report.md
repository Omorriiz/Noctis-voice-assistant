# Этап 1 — Сервер: отчёт

## Что сделано

**Новый пакет `server/noctis_server`** (вместо одного `server.py`, прежний протокол сохранён):

- **БД** (SQLAlchemy 2, Alembic): **только SQLite** (решение автора: проще развернуть и защитить в дипломе; WAL, внешние ключи, резервная копия командой `python -m noctis_server.backup`). Таблицы:
  `users, roles, sessions, password_resets, devices, user_devices, settings (настройки устройства),
  user_settings, timers, alarms, media, playlists, playlist_items, history, mqtt_topics, ota_versions`.
  Миграция `0001`, проверяется тестом (вверх и вниз).
- **Аутентификация**: JWT access (15 мин) + refresh-токены с ротацией и обнаружением повторного
  использования (кража → все сессии отзываются), пароли — scrypt, восстановление пароля одноразовым
  токеном, смена пароля, выход, удаление аккаунта (право на удаление ПДн), согласие на обработку ПДн
  при регистрации (152-ФЗ).
- **REST API** `/api/v1`: `auth/*`, `me`, `me/settings`, `devices` (CRUD, настройки, reboot,
  история: просмотр / экспорт JSON / очистка), `ota` (загрузка образа админом, выдача устройствам, sha256).
- **Защита**: ограничение частоты запросов по IP (строже для входа), CORS из настроек,
  параметризованные запросы ORM, изоляция устройств между пользователями (чужое устройство → 404).
- **WebSocket `/noctis/v1/`** (старый `/nils/v1/` оставлен для совместимости со старой прошивкой):
  - аутентификация устройства по `device_id` + `token` (анонимный режим — только по флагу);
  - **у каждого устройства своя история диалога** (раньше была общая на всех);
  - при подключении и при изменении настроек в приложении устройству приходит `config`
    (основа персонализации, этап 3); команда `reboot`;
  - аудио больше **не пишется на диск** (флаг `NOCTIS_STORE_AUDIO` только для отладки), Whisper
    получает данные из памяти;
  - диалог сохраняется в историю только если пользователь не отключил её в настройках.
- **Конфигурация**: все пути и параметры через `NOCTIS_*`/`.env`; жёстко прописанных путей к
  `C:\Users\yumit\...` больше нет.
- **LLM**: только Vikhr-Nemo-12B (по вашему решению); qwen2.5 не используется.

## Тесты

`pytest` в `server/` — **28 тестов проходят** (≈5 с, без GPU): регистрация/вход/refresh/сброс пароля,
rate limit, SQL-инъекция, права доступа, изоляция пользователей, настройки и валидация, история
(экспорт/очистка/приватность), OTA, миграции вверх/вниз, WebSocket: полный цикл с заглушкой
конвейера, отказ при неверном токене, доставка настроек и команд, раздельные настройки устройств.

## Не проверено (честно)

- Реальные модели (Whisper, Silero, Ollama/Vikhr) на этом этапе **не запускались** — конвейер
  проверен только компиляцией и заглушкой в тестах; на вашем ноутбуке нужен первый запуск
  `python -m noctis_server`.
- Отправка писем при восстановлении пароля — заглушка (токен пишется в лог в режиме разработки), этап 8.

## Замечания и решения

1. **Имя vs слово пробуждения.** Вы просили везде «Noctis», но слово пробуждения — «Нильс».
   Я считаю: продукт = Noctis, слово пробуждения по умолчанию = «Нильс» (в БД пока значение `nils`).
   Если слово пробуждения тоже должно быть «Ноктис» — скажите, это меняется одной константой.
2. Старые комментарии/логи «Nils» в оставшемся коде (`firmware/`, `site/`) переименую на соответствующих этапах.
3. Для RTX 5060 (архитектура Blackwell) нужен PyTorch с CUDA 12.8+ — отмечено в `requirements-ai.txt`.
4. Silero: большинство голосов — только для некоммерческого использования (для диплома нормально).
