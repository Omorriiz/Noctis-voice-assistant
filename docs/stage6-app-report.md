# Этап 6 — мобильное приложение: отчёт

Выполнено только то, что нужно для этапа 6. Этапы 8 и 9 не затрагивались.

## Что сделано
- **Flutter-приложение** (`app/`): вход и регистрация (с согласием на обработку данных), главный экран с выбором колонки и нижней панелью —
  **Колонка** (состояние онлайн/не в сети, название, громкость, язык, голос, характер, слово пробуждения, часовой пояс, перезагрузка),
  **Таймеры и будильники** (быстрые таймеры, обратный отсчёт, пауза, будильники по дням недели с мелодией и переключателем),
  **Музыка** (плеер колонки, библиотека, радио, Jamendo, загрузка файлов с телефона, добавление радиостанций),
  **История** (просмотр и очистка), **Профиль** (язык, тема, выход, удаление учётной записи, версия).
- **Добавление колонки по Bluetooth** (мастер): разрешения → поиск `NOCTIS_*` → код с экрана колонки → Wi‑Fi → привязка (создание устройства на сервере,
  передача колонке адреса сервера и токена через endpoint `noctis-config`, затем Wi‑Fi) → ожидание статуса «онлайн». При ошибке после создания
  устройство на сервере удаляется, «сирот» не остаётся. Порядок и формат — те же, что у `server/tools/pair_device.py`.
- **Стиль идентичен сайту**: цвета, скругления и градиенты берутся из `site/assets/tokens.json` (`tools/gen_tokens.py`), космический фон со звёздами, стеклянные карточки,
  неоновый градиент в заголовках, кнопки-градиенты, переключатель тёмной/светлой темы (тёмная по умолчанию). Тест сверяет цвета приложения с сайтом.
- **Иконка** — присланное вами изображение (Android: обычная и адаптивная иконка, iOS, веб), тот же значок в шапке приложения.
- **5 языков**: строки кабинета берутся из `site/i18n.py` (формулировки совпадают с сайтом) плюс строки приложения; язык — как в системе, иначе русский, выбор в профиле.
- **Для конечных пользователей**: адрес сервера не вводится (задаётся при сборке `--dart-define=NOCTIS_SERVER=…`), ошибки без технических подробностей.
- **Убрано**: Firebase (`firebase_*`, `google-services.json`, `firebase.json`), MQTT и прежние экраны прототипа; push-уведомлений нет. Пакет Android переименован в `app.noctis.speaker`.
- **Flutter SDK установлен** по вашему согласию: официальный 3.47.7 в `Noctis\flutter` (вне репозитория и ZIP). Скачанный архив удалён.

## Android (дополнение)
- Установлен Android SDK (по вашему согласию, лицензии приняты по вашему разрешению): платформа 37, build-tools 37, platform-tools, NDK 28.2, эмулятор и образ Android 16. Всё в `Noctisndroid-sdk` (вне репозитория).
- Собраны **подписанные** `Noctis-1.0.0.apk` (≈57 МБ) и `Noctis-1.0.0.aab` (≈56 МБ) скриптом `app/tools/build_android.ps1`; подпись проверена `apksigner` (v2, ключ «CN=Noctis»). Ключ `android/noctis-release.jks` создан локально, в репозиторий не входит.
- **Проверено на эмуляторе Android 16**: установка APK, запуск, вход в вашу учётную запись на настоящем сервере, экран колонки, мастер добавления колонки. Запрос разрешения — «Устройства поблизости» (на Android 12+ геолокация не запрашивается; на Android 11 и старше — запрашивается, этого требует система); поиск настоящего Bluetooth завершается понятным сообщением «колонки не найдены» (в эмуляторе нет Bluetooth). Тестовая учётная запись удалена.
- Для сборки пришлось: указать платформу как `37.0`, установить NDK, заменить `file_picker` 11 на 10.3 (11-я версия не совместима с режимом сборки Kotlin, который использует шаблон Flutter), добавить `device_info_plus` (чтобы не просить геолокацию на новых телефонах).
- Остаётся непроверенным: **настоящий телефон и настоящая плата по Bluetooth** — в эмуляторе Bluetooth нет.

## Не проверено / ограничения
- **Сборка для iPhone (IPA) не выполнялась**: нужен Mac с Xcode. APK и AAB для Android собраны (см. выше).
- **Настоящее Bluetooth-сопряжение с платой не проверено** — только на телефоне с платой. Предположение: endpoint `noctis-config` получает UUID характеристики `ff54` (первый пользовательский в протоколе ESP-IDF); если нет, поправить в `ble_pairing.dart` (`BleTransport.endpoints`).
- **Безопасность** (этап 8): в Android включён `usesCleartextTraffic`, потому что сервер сейчас работает по `http` в локальной сети; для публикации нужен HTTPS и выключить этот флаг. Токены хранятся в защищённом хранилище телефона.
- `flutter_blue_plus`: бесплатен для личного/учебного использования; коммерческое использование требует платной лицензии.
- Музыка с Jamendo зависит от `client_id` на сервере; воспроизведение и уведомления «колонка не в сети» проверены только на уровне интерфейса и API, не на живой колонке.
- Для сборок под Windows с плагинами Flutter просит «режим разработчика» Windows (символьные ссылки) — системную настройку я не менял; для веб-версии и тестов он не понадобился.
