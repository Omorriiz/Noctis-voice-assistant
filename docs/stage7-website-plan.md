# Этап 7 — сайт и веб-кабинет: план

Задание пользователя: доработать существующий сайт (`site/`), сделать единый стиль и палитру с будущим приложением, светлую и тёмную темы,
кабинет управления колонкой через API сервера. Сайт статический. Этапы 6, 8, 9 не затрагиваются.

## Что делаем
1. **Единые токены оформления** — `site/assets/tokens.json` (цвета светлой и тёмной тем, радиусы, шрифты). Из него `build.py` собирает CSS сайта;
   приложение (этап 6) возьмёт те же значения.
2. **Переключатель темы** светлая/тёмная: по умолчанию как в системе, выбор запоминается в браузере, без «вспышки» при загрузке.
3. **Пять языков** (ru — основной, en, es, de, fr): `/` (ru), `/en/`, `/es/`, `/de/`, `/fr/`; в каждом лендинг и кабинет, переключатель языка.
4. **Лендинг** переписан под реальный продукт: возможности, как работает, голосовые команды, приватность, железо, контакты.
   Прежний текст про «тренды ESP32» и кнопки загрузки приложения (приложения ещё нет) убираются.
5. **Кабинет** (`dashboard.html`) на чистом JavaScript, только через API сервера: вход/регистрация, колонки и их состояние,
   настройки (громкость, язык, голос, характер, слово пробуждения, часовой пояс), таймеры и будильники, музыка (библиотека, радио, Jamendo, плеер),
   история диалогов. Адрес сервера задаётся в кабинете.
6. **Без внешних запросов**: системные шрифты, никаких CDN, счётчиков и сторонних скриптов.
7. **Статичность**: готовые HTML лежат в репозитории; `build.py` нужен только при правке текстов.

## Чего не делаем
Регистрации колонки по Bluetooth (это в приложении), загрузки прошивки, администрирования, push-уведомлений, любых серверных частей сайта.

## Проверка
Автотесты сборки (все языки, все ключи, ссылки, отсутствие внешних адресов, экранирование), проверка кабинета в браузере против работающего сервера.
