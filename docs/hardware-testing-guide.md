# Руководство по проверке колонки на плате

Всё делается со страницы `http://localhost:8000/console` и журнала платы. Журнал платы (UART): `server\tools\board_log.py`
(`..\..\tools_venv\Scripts\python.exe` из папки `server` — там есть pyserial). Одновременно журнал может читать только одна программа.

## 0. Что нужно подготовить

* Сервер запущен (`python -m noctis_server`), колонка в статусе «● онлайн».
* Для OTA и загрузки моделей слов нужна роль администратора. Один раз, с вашим email:
  `.venv\Scripts\python.exe -c "import sqlite3; c=sqlite3.connect('data/noctis.db'); c.execute(\"update users set role_id=(select id from roles where name='admin') where email='ВАШ_EMAIL'\"); c.commit()"`
  (затем выйдите и войдите на странице заново, чтобы получить токен с ролью).

## 1. Слово пробуждения «Нильс» (если колонка не реагирует)

1. Запустите запись журнала: `python tools\board_log.py record --port COM5 --out wake.log` (в другом окне — подключитесь не нужно, пишет сам).
2. Скажите «Нильс» 10 раз с расстояния 0,5–1 м обычным голосом. В журнале при звуке или «почти узнавании» появятся строки
   `[слух] вероятность слова 0.xx, пик N из 32767, клиппинг K`.
3. Читайте результат:
   * вероятность 0,80 и выше — слово срабатывает (порог сейчас 0,80, окно 5);
   * 0,4–0,8 — слово «почти»: понизьте порог (шаг 4);
   * ниже 0,3 при чётком произнесении — модель не совпадает с вашим голосом: запишите свои образцы и переобучите (`wakeword\README.md`);
   * «клиппинг» постоянно > 0 при разговоре — слишком большое усиление микрофона (`MIC_SHIFT` в `main.c`: 14 = +12 дБ, 15 = +6 дБ);
   * «пик» при речи < 3000 — слишком тихо: ближе к колонке, либо `MIC_SHIFT` 13.
4. Сменить чувствительность без перепрошивки:
   `python ..\wakeword\retune_model.py --in ..\wakeword\models\nils.nwwm --cutoff 0.70 --window 4 --upload http://192.168.0.136:8000 --token <токен администратора>`
   (токен — в журнале страницы `/console`: запрос `POST /api/v1/auth/login`, поле `access_token`). Колонка скачает модель сама (≈ 5 с, перезапуск).
   Таблица «полнота / ложные срабатывания» по порогам — `wakeword\models\nils_eval_irina_window*.json` (на синтетике; на живом голосе хуже).
5. Односложное слово «Нильс» трудное для детектора. Надёжнее фраза из 3–4 слогов: «Эй, Нильс» (`custom:Эй Нильс`, обучение ≈ 40 мин).

## 2. Радио

1. Раздел «5. Музыка» → «Интернет-радио»: название и ссылка на **MP3**-поток (AAC и HLS/`.m3u8` не поддерживаются), «Добавить станцию».
   Проверенные на момент написания потоки (audio/mpeg, отвечают):
   * Rock FM — `http://nashe1.hostingradio.ru/rock-128.mp3`
   * Вести ФМ — `http://icecast.vgtrk.cdnvideo.ru/vestifm_mp3_192kbps`
   * Спокойное радио — `https://listen9.myradio24.com/6262`
   * Relax FM Chillout — `https://pub0201.101.ru/stream/trust/mp3/128/24`
   Другие: https://www.radio-browser.info (фильтр codec = MP3), копируйте «URL потока».
2. Нажмите ▶ у станции или скажите «Нильс, включи радио Рок». Ожидается: через 2–4 секунды звук; в журнале платы `music: Трек: … (radio)`.
3. Проверьте «пауза», «дальше», «стоп», «громче». На 5–10 минут оставьте играть: в конце журнал платы пишет
   `Конец потока (потеряно N Б, опустошений буфера M)` — M и N должны быть 0 или единицы.
4. Радио — живой поток, он не кончается: остановите кнопкой «Стоп» или голосом.

## 3. Jamendo

1. Зарегистрируйтесь на https://developer.jamendo.com, создайте приложение, возьмите **client_id**.
2. В `server\.env` добавьте строку `NOCTIS_JAMENDO_CLIENT_ID=ваш_id`, перезапустите сервер.
3. Страница `/console` → Jamendo → введите `jazz` → «Найти» (список треков) → ▶. Голосом: «Нильс, включи джаз из Джамендо».
4. Без client_id страница покажет «Jamendo не настроен» — это нормально. Треки имеют лицензии Creative Commons (указаны в данных).

## 4. Обновление по воздуху (OTA)

1. Версия в прошивке: `firmware\components\noctis_core\include\noctis_core.h`, строка `#define NOCTIS_FIRMWARE_VERSION "0.4.0"`.
   Обновление принимается только **вперёд**: поставьте `"0.4.1"`.
2. Соберите (колонку не прошивайте): в `firmware` — `..\..\tools_venv\Scripts\pio.exe run`. Образ: `.pio\build\esp32-s3-devkitc-1\firmware.bin`.
3. Страница `/console` → «6. История и обновление» → версия `0.4.1`, выберите `firmware.bin` → «1. Загрузить образ» → «2. Отправить на колонку» → «Статус».
4. Ожидается в журнале платы: скачивание, `Обновление 0.4.1 записано, перезагрузка`, затем `Первый запуск обновления … жду подтверждения`
   и через несколько секунд `Прошивка 0.4.1 подтверждена`. В таблице устройств версия станет 0.4.1.
5. Проверка отката (по желанию): соберите `0.4.2` с `abort();` первой строкой `app_main`, отправьте. Колонка уйдёт в перезагрузку и сама вернётся на 0.4.1
   (новая прошивка не подтвердила работу). Потом прошейте нормальную версию по USB.
6. Если «Версия … не новее текущей» — увеличьте номер. Если «SHA-256 не совпал» — образ повреждён при загрузке: повторите.

## 5. Остановка будильника кнопкой BOOT

1. Поставьте будильник через 1–2 минуты (страница `/console` → «4. Таймеры и будильники», или голосом «Нильс, разбуди меня в …»), мелодия `beeps`.
2. Когда зазвонит, **коротко нажмите BOOT** (не удерживайте, и не нажимайте при включении питания).
3. Ожидается: звонок сразу умолкает; в журнале платы `Звонок остановлен кнопкой`; сервер получает `ring_stopped`.
4. Другие способы остановки: слово «Нильс» и любой ответ сервера (звонок умолкает сам через 60 с).
5. Кроме того: будильник звонит и без связи с сервером (выключите Wi-Fi роутера до срабатывания, когда расписание уже на плате).

## 6. Длительная работа

1. Запись на ночь (не перезагружает плату): `python tools\board_log.py record --port COM5 --out board-night.log --hours 12`
   (после USB-обрыва переподключается сам). Не открывайте в это время другой монитор порта.
2. Колонка должна всё это время стоять в обычных условиях: питание от блока, а не от USB-хаба; несколько команд голосом вечером и утром.
3. Утром: `python tools\board_log.py analyze board-night.log`. Смотрите:
   * перезагрузки и падения — должно быть 0;
   * обрывы Wi-Fi — сейчас 1 раз в 2–4 минуты (причина на стороне роутера, см. отчёт); важно, что связь каждый раз восстанавливается;
   * внутренняя память: свободно не должно убывать от начала к концу (иначе утечка), минимум > 8 КБ;
   * минимальный запас стека любой задачи > 600 Б.
4. Для проверки в течение суток и более: то же с `--hours 24`. Вердикт печатается в последней строке.

## 7. Качество звука

1. Сгенерируйте тестовые файлы: `python tools\make_test_audio.py --out test_audio` и загрузите их на странице («Моя библиотека»).
2. Слушайте с расстояния около метра при громкости 40 %, 70 %, 100 % (`PATCH` настроек или раздел «3. Настройки»):

| Файл | Что проверяет | Нормально |
|---|---|---|
| `01_tone_1khz_steps` | искажения по уровням | чистый тон до −10 дБ; хрип/«рваность» только на −3 дБ и на громкости 100 % |
| `02_sweep_100_7000hz` | резонансы, дребезг корпуса | плавный подъём без провалов и дребезга; ниже ~150 Гц звука мало (малый динамик) |
| `03_melody_c_major` | ровность, «плавание» | ноты ровные, без щелчков между ними |
| `04_clicks_silence` | шипение усилителя, щелчки | в тишине нет шипения/гула; при старте и остановке — без громкого «щелчка» |
| `05_speech_band_noise` | общий тембр | ровный «шум водопада»; нет пульсаций |

3. Мелодии будильников: `default`, `soft`, `rooster`, `beeps` (список при создании будильника) — различаются и не «рвутся».
4. Речь (Ксения/мужской голос): «Нильс, расскажи про погоду» — слова разборчивы, нет «ступенек» между фразами.
5. Запись микрофона: `NOCTIS_STORE_AUDIO=true` в `server\.env`, перезапуск сервера — последняя фраза каждого подключения сохраняется в
   `server\data\output\<id>_input.wav`. Послушайте, как слышит колонка: фоновый шум, «эхо» комнаты, не обрезаются ли начало и конец.
   После проверки верните `false` (голос пользователей не должен храниться).
6. Ограничения формата: колонка играет 16 кГц моно (до 8 кГц); музыка играет на 50 % громкости колонки, чтобы слышать команды (эхоподавления нет).

## 8. Шутки и истории

Модели Vikhr по умолчанию склонны к шуткам про компьютеры. В запросах «расскажи анекдот / шутку / историю / сказку» сервер добавляет
случайную бытовую тему (животные, еда, семья, погода…) только в запрос к модели. Темы — `personalization.py` (`_TOPICS`), их можно менять.
