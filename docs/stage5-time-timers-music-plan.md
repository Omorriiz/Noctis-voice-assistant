# Этап 5 — Время, таймеры, будильники, музыка: план

Noctis — платформа; Nils (Нильс) — слово пробуждения и имя ассистента. БД — SQLite (Alembic). Всё работает нативно на Windows.
Этапы 6–9 (приложение, сайт, безопасность/документация, диплом) не затрагиваются.

## Цели

1. **Время без RTC**: NTP на плате + синхронизация с сервером (`time_sync`); голосом — «который час / какое сегодня число»; время на OLED.
2. **Таймеры**: поставить, пауза/продолжить, отменить, «сколько осталось»; переживают перезагрузку; по окончании — звук + голосовое уведомление (без push).
3. **Будильники**: время, дни недели или однократно, свой часовой пояс; хранятся в БД сервера **и** в NVS платы; звонят даже без связи с сервером.
4. **Музыка**: 3 источника — собственная библиотека, Jamendo API (CC-лицензии), интернет-радио (и только они); пауза/стоп/следующий/предыдущий/громкость, вежливые ответы «не найдено».
5. Голосовые команды на 5 языках (ru, en, es, de, fr), разбор без LLM (быстро и предсказуемо); всё остальное — как раньше, через Vikhr.
6. REST-API для будущего приложения (таймеры, будильники, библиотека, радио, плеер).

## Архитектура

```
 голос → Whisper → intents.parse(текст, язык) ─┬─ нет совпадения → Vikhr (как раньше)
                                                └─ команда → skills.run → ответ фразой (TTS) + действие
 server/noctis_server/
   numwords.py   числа словами и обратно (5 языков)         timeutil.py  местное время, фразы времени/даты
   intents.py    разбор команд (время, таймер, будильник, музыка, громкость)
   skills.py     выполнение команд, ответы на языке устройства
   scheduler.py  CRUD таймеров/будильников + цикл срабатывания (1 с) + снимок расписания для платы
   media/        library.py (папка пользователя, теги mutagen) · jamendo.py · radio.py · decoder.py (miniaudio → PCM16 16 кГц) · player.py
   routers/      schedule.py (timers, alarms) · media.py (библиотека, радио, jamendo, плеер)
 протокол      →устройство: time_sync, schedule, music_start/chunk/end/pause/resume/stop, command stop_ring
               ←устройство: sched_event {kind,id}
 firmware/
   noctis_core:  noctis_sched.c (таймеры/будильники: разбор, опрос, сериализация с CRC) · noctis_ring.c · мелодии · разбор time_sync/schedule/music
   main/:        clock.c (SNTP + сервер) · sched_task.c (NVS, срабатывание, звонок) · music.c (буфер → I2S) · OLED: часы
```

Решения:
* **Расписание живёт на плате** (NVS), сервер присылает снимок `schedule` при подключении и каждом изменении, плата сама срабатывает
  по времени — будильник сработает без Wi-Fi. Сервер срабатывает параллельно и добавляет *голосовое* уведомление (если плата онлайн);
  повторные срабатывания гасятся (`last_fired_key` у будильника, состояние таймера).
* **Музыка идёт потоком PCM16 16 кГц через WebSocket** (как ответы TTS): плата не декодирует MP3 (нет кодека/ESP-ADF). Сервер декодирует
  (miniaudio: MP3/FLAC/Vorbis/WAV; без ffmpeg) и отправляет в реальном времени с опережением ≈ 1,5 с. Пауза/стоп — сообщения плате.
* Во время команды голосом музыка ставится на паузу автоматически (сервер видит `start_recording`) и продолжается после ответа,
  если команда не про музыку. **Нет эхоподавления (AEC)**: при громкой музыке слово пробуждения распознаётся хуже — громкость музыки
  = 50 % от общей по умолчанию.
* Источники ограничены тремя: `local`, `jamendo`, `radio` (проверяется на уровне модели/API).
* Часовой пояс устройства (`settings.timezone`, IANA); смещение UTC передаётся в `time_sync` при подключении и раз в час.

## План тестов

* числа ↔ слова во всех 5 языках (0–999, падежи ru), разбор длительностей и времени суток;
* ≥ 8 фраз на каждый из 5 языков по каждому классу команд + «не команда» (вопросы к LLM не перехватываются);
* таймеры/будильники: создание, пауза, срабатывание, повторы по дням недели, часовой пояс, переход через полночь, перезапуск сервера;
* Си-ядро: опрос расписания, сериализация/CRC, повреждённый NVS, переполнение, время ещё не синхронизировано;
* виртуальная колонка: полный цикл «голос → таймер → срабатывание → звонок → остановка», перезагрузка платы с сохранённым расписанием;
* музыка: библиотека (теги), Jamendo (мок HTTP), радио (локальный HTTP-поток), плеер (пауза/следующий/предыдущий/стоп/конец), не найдено;
* регрессия: все тесты этапов 1–4.

## Критерии приёмки

1. «Поставь таймер на 5 минут» (все 5 языков) → запись в БД, снимок на плату, по истечении — звонок и голосовое «Таймер завершён».
2. Таймеры и будильники сохраняются после перезапуска сервера и после «перезагрузки» виртуальной платы.
3. «Разбуди меня в 7:30 по будням» → будильник пн–пт, срабатывает один раз в минуту, однократный отключается после звонка.
4. «Включи музыку / радио …/ Jamendo …» запускает поток; «стоп/пауза/дальше/назад/громче» работают; ненайденное → вежливый ответ.
5. Все тесты зелёные (этапы 1–5), прошивка собирается `pio run`, документация и отчёт обновлены.

## Что нельзя проверить без платы / сети (замены)

Звучание I2S, OLED, SNTP в реальной сети, пропускная способность WebSocket для музыки на ESP32 — не проверяются; логика покрыта хост-тестами и
виртуальной колонкой. Jamendo — мок (нужен собственный `NOCTIS_JAMENDO_CLIENT_ID`); радио проверяется на локальном потоке.
