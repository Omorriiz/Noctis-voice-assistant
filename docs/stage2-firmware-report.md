# Этап 2 — Прошивка: отчёт

Названия: **Noctis** — платформа, **Nils (Нильс)** — слово пробуждения и имя ассистента (не менялись).
План этапа: [stage2-firmware-plan.md](stage2-firmware-plan.md). Версия прошивки: **0.2.0**.

## Что сделано

**Прошивка (`firmware/`)**
- **Сопряжение по BLE** (`provisioning.c`): `wifi_provisioning`, безопасность 1; код сопряжения (8 цифр,
  случайный, хранится в NVS) показывается на экране и в логе. Собственный endpoint `noctis-config`
  принимает адрес сервера, `device_id` и токен — вместо зашитых в `config.h` Wi-Fi и IP.
- **Хранилище NVS** (`settings.c`): ссылка на сервер, персонализация (слово пробуждения, голос,
  характер, язык, громкость, часовой пояс, ревизия), сброс к заводским (BOOT 5 с или команда сервера).
- **Аутентификация на сервере**: заголовки `X-Device-Id` / `X-Device-Token` (секрет не в URL и не в логе);
  повтор подключения с нарастающей паузой 5→60 с.
- **Персонализация без перепрошивки** (`control.c`): сообщение `config` проверяется, сохраняется в NVS
  и применяется (громкость — сразу); `device_info` при подключении; команды `reboot`, `factory_reset`, `ota`.
- **OTA** (`ota.c`): образ скачивается с адреса, построенного из сохранённой ссылки на сервер (адрес
  из команды игнорируется), SHA-256 проверяется до переключения слота, только обновление вперёд,
  откат, если новая версия не подтвердила работу за 90 с.
- **Экран SSD1306** (`display.c`): экраны сопряжения, статуса, ошибки, ожидания; без экрана работает как раньше.
- **Таблица разделов 16 MB**: `ota_0` 3M, `ota_1` 3M, `model` 8M (esp-sr), `wakeword` 1M (этап 4),
  `storage` ≈0,9M (сигналы, этап 5). Приложение занимает 1,96 MB из 3 MB слота.
- **Переносимая логика** `components/noctis_core` (проверка настроек, разбор сообщений, версии,
  SHA-256 hex, сборка адресов) — без ESP-IDF, поэтому тестируется на ПК.

**Сервер (`server/`)**: приём `device_info` / `ota_status`; `POST /devices/{id}/ota` и
`GET /devices/{id}/ota` (запуск и статус обновления); API прошивки `GET /api/v1/device/ota/{version}`
и `GET /api/v1/device/config` с аутентификацией устройства; тесты больше не пишут в `data/ota`.

**Инструменты**: `server/tools/virtual_speaker.py` — виртуальная колонка, разбор сообщений которой
выполняет *настоящий* Си-код прошивки (библиотека через ctypes).

## Результаты проверки

| Проверка | Результат |
|---|---|
| Сборка прошивки `pio run` (ESP-IDF 5.4, esp-sr, NimBLE) | **успешно**, без предупреждений; Flash 1,96 MB из 3 MB, RAM 25,6 % |
| Хост-тесты Си-логики (`firmware/tests`, UBSan) | **83 проверки, 0 ошибок** |
| `pytest` сервер (этап 1 + интеграция с виртуальной колонкой) | **40 тестов проходят** |

Интеграционные тесты покрывают: валидацию данных сопряжения (защита от инъекции в URL), аутентификацию
по заголовкам и отказ при неверном токене, сохранение `config` и его переживание перезагрузки, живую
доставку смены настроек, голосовой цикл, `reboot`/`factory_reset`/неизвестную команду, успешный OTA
(переключение слота), OTA с неверным SHA-256 (старая версия остаётся), отказ от понижения версии,
права доступа и аутентификацию устройства.

## Что НЕ проверено (нужна плата, или ограничения)

Собрано и проверено на уровне компиляции и логики, но **не запускалось на реальном ESP32-S3**:
BLE-сопряжение с приложением (приложение — этап 6), экран SSD1306 (пины SDA=8, SCL=9, адрес 0x3C —
подтвердите по вашей схеме), работа I2S/WakeNet после изменений, реальный OTA и откат,
повтор подключения. Голосовой конвейер на сервере по-прежнему проверен только с заглушкой (модели не запускались).
Чек-лист для платы — ниже. Это относится и к исходной прошивке: пользовательские настройки в `main.c`
аудио-части не менялись, кроме громкости.

## Чек-лист первого запуска на плате

1. `pio run -t erase`, затем `pio run -t upload` (раздел `model` переехал на `0x620000`).
2. Монитор: «Устройство не сопряжено — запускаю BLE-сопряжение», на экране `NOCTIS_XXXXXX` и код.
3. Создать устройство через API (`/docs` → `POST /api/v1/devices`), проверить сопряжение тестовым
   BLE-клиентом (nRF Connect / `esp_prov.py` из ESP-IDF) или дождаться приложения.
4. После подключения: `device_info` на сервере, `GET /devices/{id}` показывает `online: true`.
5. Смена громкости/характера через `PATCH /devices/{id}/settings` — в логе «Настройки обновлены».
6. Перезагрузка: настройки сохранились. BOOT 5 с — сброс.
7. OTA: загрузить образ (`PUT /api/v1/ota/0.2.1`), `POST /devices/{id}/ota` — проверить статус и откат
   (образ с ошибкой подключения должен откатиться через 90 с).

## Замечания и решения

1. **Слово пробуждения.** Сервер и NVS хранят `nils` по умолчанию, но модель на плате пока «Привет ESP»
   (смена модели — этап 4). Экран показывает хранимое слово.
2. **Старый `config.h`** с Wi-Fi/IP продолжит собираться (макросы просто не используются); образец обновлён.
3. **Обратная совместимость сервера:** анонимный режим и путь `/nils/v1/` оставлены, пока включён флаг;
   в продакшне `NOCTIS_ALLOW_ANONYMOUS_DEVICES=false`.
4. **Токен устройства — по HTTP/WS без TLS в локальной сети.** Для публичного сервера нужен `wss/https`
   (поле `tls` уже поддерживается); защита транспорта и подпись образов OTA — этап 8.
5. Шрифт экрана (Adafruit-GFX, BSD) — только латиница/цифры; кириллица на экране заменяется `?`.
6. PlatformIO скачивает esp-sr из ветки `master` (так было и раньше) — для воспроизводимости сборки
   стоит зафиксировать коммит перед защитой.
