# Noctis — прошивка колонки (ESP32-S3)

Прошивка превращает плату ESP32-S3 в умную колонку: она слушает микрофон, ждёт слово пробуждения («Нильс» или «Alexa»), отправляет команду на сервер Noctis
и проигрывает ответ, музыку и сигналы будильников. Версия прошивки — `NOCTIS_FIRMWARE_VERSION` в `components/noctis_core/include/noctis_core.h`.

## Как работает

1. Колонка слушает микрофон INMP441. Слово пробуждения распознаётся прямо на плате; пока оно не прозвучало, на сервер ничего не уходит.
2. Слово услышано — короткий сигнал и запись команды. Пауза в речи около 0,7 с заканчивает запись, команда уходит на сервер по WebSocket.
3. Ответ сервера (речь, музыка) звучит через усилитель MAX98357A. Пока колонка говорит, слово пробуждения не слушается, поэтому динамик не «будит» сам себя.
4. Если после слова ничего не сказать 6 секунд, прозвучит низкий сигнал и колонка вернётся к ожиданию.

Часы работают без отдельного модуля времени: время приходит по SNTP, а если сети нет в первые секунды — от сервера. Пока время неизвестно, на экране `--:--`, будильники молчат.

## Оборудование

| Компонент | Подключение |
|---|---|
| Плата | ESP32-S3 DevKitC-1 **N16R8** (16 МБ flash, 8 МБ PSRAM) — PSRAM обязательна для распознавания слова |
| Микрофон INMP441 | BCK = GPIO17, WS = GPIO18, SD = GPIO16, L/R → GND, VDD → 3,3 В |
| Усилитель MAX98357A | BCLK = GPIO5, LRC = GPIO6, DIN = GPIO7 |
| Экран SSD1306 (I²C, 0x3C) | SDA = GPIO8, SCL = GPIO9 |
| Внешняя кнопка (по желанию) | один контакт на GPIO11, другой на GND; резистор не нужен — включена внутренняя подтяжка. Провод короче ≈ 20 см |

Пины задаются в `include/config.h`. Файл не хранится в репозитории: скопируйте `include/config.h.sample` в `include/config.h` и при необходимости поправьте.

## Установка и прошивка

Отдельно устанавливать ESP-IDF не нужно: PlatformIO скачает его сам.

1. Установите PlatformIO: `pip install platformio` (или расширение PlatformIO для VS Code).
2. Скопируйте `include/config.h.sample` в `include/config.h`.
3. В `platformio.ini` укажите свой COM-порт (`upload_port`, `monitor_port`; по умолчанию `COM5`) — тот порт платы, что помечен UART.
4. Соберите и прошейте:

   ```powershell
   cd firmware
   pio run -t upload
   ```

   Первая сборка идёт несколько минут: скачиваются ESP-IDF, esp-sr и другие компоненты. После прошивки приложения скрипт `flash_models.py` сам собирает и записывает модели esp-sr
   (журнал — строки `[models]`). Только модели, без приложения: `pio run -t flash_models`.
5. Журнал платы: `pio device monitor`.

Если PlatformIO «зависает» при прошивке на Windows, задайте `NOCTIS_SKIP_MODELS=1` (пропустить модели при повторной прошивке приложения) и `PYTHONUTF8=1`.

Скорость прошивки в `platformio.ini` — `upload_speed = 115200` (надёжно, но модели пишутся долго); на хорошем кабеле можно поставить `460800` или `921600`.

Вместо PlatformIO подойдёт и чистый ESP-IDF 5.x (не 6.x): `idf.py set-target esp32s3`, `idf.py build`, `idf.py -p COM5 flash monitor`.

После изменения `sdkconfig.defaults` удалите созданный файл `sdkconfig.esp32-s3-devkitc-1`, чтобы настройки применились. После изменения `partitions.csv` перепрошейте всё: `pio run -t erase`, затем `pio run -t upload`.

## Слово пробуждения

Слово из настройки колонки обслуживает один из двух движков (выбирается при загрузке):

| Слово | Движок | Где модель |
|---|---|---|
| `nils` («Нильс», по умолчанию) | microWakeWord (TFLite Micro, `components/noctis_wakeword`) | раздел `wakeword`, контейнер NWWM |
| `alexa` | esp-sr WakeNet | раздел `model` (прошивается вместе с приложением) |

- Смена слова сохраняется, и колонка сама перезапускается в нужный движок; перепрошивка не нужна.
- Модель «Нильс» приходит с сервера: в `config` есть `wake_model {sha256, size}`; если хэш отличается от установленного, колонка скачивает контейнер, проверяет SHA-256 и структуру **до** записи,
  пишет его в раздел `wakeword` и перезагружается.
- Нет модели или она повреждена: колонка временно работает на запасном слове и показывает `NO WAKE MODEL`, пока сервер не пришлёт модель.
- Обучение своей модели — в [`../wakeword/README.md`](../wakeword/README.md).

## Сопряжение и настройка сети

Wi‑Fi и адрес сервера в код не зашиваются.

1. Первый запуск (или после сброса): колонка включает Bluetooth и показывает на экране имя `NOCTIS_XXXXXX` и 8-значный **код сопряжения**.
2. Приложение создаёт колонку на сервере и получает идентификатор и токен устройства (токен показывается один раз).
3. Приложение подключается по BLE (протокол Espressif `wifi_provisioning`, код сопряжения = Proof-of-Possession), сначала отправляет в endpoint `noctis-config` JSON
   `{"server":"192.168.1.5:8000","tls":false,"device_id":"…","token":"…"}`, затем — сеть Wi‑Fi.
4. Колонка подключается к сети и серверу (заголовки `X-Device-Id` и `X-Device-Token`; токен не попадает ни в адрес, ни в журнал), получает настройки и запоминает их в NVS.

Без приложения колонку можно сопрячь с компьютера: `server\tools\pair_device.py`.

### Кнопка

Работает любая из двух: BOOT (GPIO0) или внешняя на GPIO11. Короткое нажатие ничего не делает.

- Удержание **3 с** во время работы (не во время звонка) — режим настройки по Bluetooth на 10 минут: смена Wi‑Fi или адреса сервера, личность колонки (`device_id`, токен) сохраняется.
- Удержание **5 с при включении питания** — сброс к заводским настройкам. Работает с внешней кнопкой на GPIO11; BOOT при включении переводит ESP32-S3 в режим загрузчика, так что для сброса используйте GPIO11.
- Без связи с сервером 10 минут колонка сама входит в режим настройки (через 2 минуты на экране появляется подсказка).

Сброс также выполняет команда `factory_reset` с сервера (она приходит при удалении колонки в кабинете) или полное стирание платы: `pio run -t erase` и прошивка.

Настройки колонки (`wake_word`, `voice_gender`, `character_id`, `language`, `volume`, `timezone`, домашний город) хранятся в NVS, переживают перезагрузку и обновляются с сервера на лету.

## Таймеры, будильники, музыка

| Сообщение | Направление | Что делает колонка |
|---|---|---|
| `time_sync {epoch, utc_offset}` | сервер → колонка | ставит время, если SNTP ещё не сработал; запоминает часовой пояс |
| `schedule {rev, timers[], alarms[]}` | сервер → колонка | полный снимок расписания в NVS (с контрольной суммой); повреждённый блок игнорируется, сервер присылает заново |
| `sched_event {kind, id}` | колонка → сервер | таймер или будильник сработал |
| `ring_stopped` | колонка → сервер | звонок остановлен кнопкой или словом пробуждения |
| `command {name: "stop_ring"}` | сервер → колонка | голосовое «стоп» во время звонка |
| `command {name: "set_wifi", …}` | сервер → колонка | переход в другую сеть Wi‑Fi; если за 45 с нет сети и связи с сервером — откат на прежнюю |
| `wifi_result {request_id, state, error}` | колонка → сервер | итог смены сети |
| `music_start/chunk/end/pause/resume/stop` | сервер → колонка | PCM16 16 кГц моно кусками по 100 мс (base64) → буфер в PSRAM → динамик |

Звонок играет одну из мелодий (`default`, `soft`, `rooster`, `beeps`) до 60 секунд; останавливают его кнопка, слово пробуждения или команда «стоп».
Музыка играет в режиме ожидания; на время команды сервер ставит её на паузу. Эхоподавления нет, поэтому при громкой музыке слово пробуждения распознаётся хуже.
На главном экране — время, слово пробуждения, ближайший таймер и будильник или название трека; сообщения об ошибках, обновлении и сопряжении временно перекрывают его.

## Обновление по воздуху (OTA)

Сервер присылает `command {name: "ota", version, sha256, size}`. Колонка скачивает образ с адреса, построенного из сохранённой ссылки на сервер (адрес из команды не используется),
пишет его в неактивный слот, сверяет SHA-256 **до** переключения и перезагружается. Обновление идёт только вперёд. Новая версия должна за 90 секунд подключиться к серверу и получить настройки,
иначе загрузчик откатывает прежнюю.

## Структура

```
platformio.ini            настройки PlatformIO (ESP-IDF)
flash_models.py           сборка и запись моделей esp-sr (запускается автоматически)
partitions.csv            16 МБ: nvs, otadata, ota_0 и ota_1 (по 3 МБ), model (8 МБ, esp-sr), wakeword (1 МБ, microWakeWord), storage
sdkconfig.defaults        PSRAM, esp-sr, BLE (NimBLE), откат OTA
include/config.h.sample   образец config.h: пины и тонкая настройка
main/main.c               аудио-конвейер: микрофон → распознавание слова → WebSocket → динамик
main/settings.c           хранилище NVS
main/provisioning.c       BLE-сопряжение
main/netwatch.c           кнопки, контроль связи, режим повторной настройки
main/control.c            команды сервера (reboot, factory_reset, ota, set_wifi)
main/ota.c                обновление по воздуху
main/display.c            экран SSD1306
main/clock.c              время (SNTP + сервер)
main/schedule.c           таймеры и будильники
main/music.c              плеер музыки
main/wakeword_sync.c      загрузка модели слова с сервера
components/noctis_core/   переносимая Си-логика (настройки, сообщения, контейнер NWWM, расписание, буфер плеера) — тестируется на компьютере
components/noctis_wakeword/   детектор microWakeWord: микро-фронтенд + TFLite Micro
tests/                    тесты Си-логики на компьютере
legacy/                   прежняя Arduino-прошивка (не собирается, только для справки)
```

Тесты логики прошивки (нужен gcc или clang, либо `pip install ziglang`): `python tests/run_host_tests.py`.

## Настройки

| Где | Параметр | Что делает |
|---|---|---|
| `main/main.c` | `VAD_END_SILENCE_MS` (700) | пауза, после которой команда считается законченной |
| `main/main.c` | `NO_SPEECH_TIMEOUT_MS` (6000) | сколько ждать команду после слова |
| `main/main.c` | `MIC_SHIFT` (14) | усиление микрофона: меньше число — громче |
| `include/config.h` | `MAX_RECORD_SECONDS` (10) | максимальная длина команды |
| `include/config.h` | `MIC_USE_RIGHT_CHANNEL` | если L/R микрофона подключён к 3,3 В |
| `include/config.h` | `OLED_I2C_SDA/SCL` (8/9) | пины экрана |

## Протокол с сервером

Путь WebSocket — `/noctis/v1/`. Колонка → сервер: `start_recording`, `audio_chunk {index, data}` × N, `stop_recording`; служебные `device_info {firmware, config_revision, free_heap, reset_reason}`, `ota_status {version, state, error}`.
Сервер → колонка: `hello`, `config {wake_word, voice_gender, character_id, language, volume, timezone, revision, …}`, `command`, `text_response`, `audio_response_start/chunk/end`.

Звук в обе стороны — **PCM16, моно, 16 кГц, little-endian, без заголовка WAV**; сервер сам приводит озвучивание к 16 кГц.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `Модели esp-sr не найдены в разделе "model"` | модели не прошиты: `pio run -t flash_models` |
| `[models] esp-sr не найден в managed_components` | сначала соберите проект (`pio run`), потом прошивайте |
| Слово не распознаётся | говорите чётко с расстояния 0,5–2 м; можно попробовать `MIC_SHIFT 13` |
| Срабатывает само | уменьшите усиление (`MIC_SHIFT 15`) |
| Команда обрезается | увеличьте `VAD_END_SILENCE_MS` (например, 1000) |
| Слово услышано, но сервер не подключён | сервер не запущен или неверные данные сопряжения: удержите кнопку 3 с и настройте по Bluetooth либо сбросьте колонку |
| На экране `SERVER ERROR` | несколько неудачных подключений подряд: проверьте сервер и сеть (повтор с паузой до 10 с) |
| `Устройство не сопряжено — запускаю BLE-сопряжение` | нормально после сброса: откройте приложение и введите код с экрана |
| Порт COM занят при прошивке | закройте монитор порта и другие программы, читающие этот порт |

Результаты проверки на плате и руководство по проверке — [`../docs/hardware-test-report.md`](../docs/hardware-test-report.md), [`../docs/hardware-testing-guide.md`](../docs/hardware-testing-guide.md).
